# Ресинхронизация только части файла

> Сдвиг появился посередине — после склейки или вставленной сцены — поэтому сдвигать нужно только более поздние реплики.

## Сценарий

Первая половина файла синхронизирована, но где-то в середине (часто в месте склейки двух
источников) тайминг съезжает и остаётся неправильным до конца. Сдвиг всего файла сломает
ту часть, которая уже правильная. Нужно переместить только затронутый диапазон.

## Используемые команды

- `sm detect-offset` — измерить сдвиг на рассинхронизированном участке
- `sm delay` ★ — сдвинуть только диапазон реплик, по индексу или по временно́й метке

## Файлы-примеры

`joined.srt` — реплики 1–2 в порядке, реплики 3–4 пришли на 500 мс раньше после склейки:

```srt
1
00:00:01,000 --> 00:00:03,000
Part one line A.

2
00:00:04,000 --> 00:00:06,000
Part one line B.

3
00:00:10,000 --> 00:00:12,000
Part two line A.

4
00:00:13,000 --> 00:00:15,000
Part two line B.
```

## Пошаговая инструкция

### 1. Сдвиг по диапазону индексов

Переместить реплики 3–4 на +500 мс, оставив 1–2 нетронутыми. Сначала предварительный просмотр:

```bash
sm delay --range 3-4 --dry-run joined.srt +500
```

```
Dry-run: time offset would be applied

Offset: 500 ms
Range: 3-4
Subtitles affected: 2

Sample (first 3 subtitles):
  [1] 00:00:01,000 --> 00:00:03,000  =>  00:00:01,000 --> 00:00:03,000
  [2] 00:00:04,000 --> 00:00:06,000  =>  00:00:04,000 --> 00:00:06,000
  [3] 00:00:10,000 --> 00:00:12,000  =>  00:00:10,500 --> 00:00:12,500
```

Перемещаются только реплики 3–4 (`Subtitles affected: 2`); пример подтверждает, что 1 и 2
не изменились.

### 2. Или сдвиг по временно́й метке

Когда вы знаете момент, но не индекс, используйте `--from-timestamp` — каждая реплика
начиная с этого момента или позже будет сдвинута:

```bash
sm delay --from-timestamp 00:00:09,000 --dry-run joined.srt +500
```

```
Dry-run: time offset would be applied

Offset: 500 ms
From timestamp: 00:00:09,000
Subtitles affected: 2

Sample (first 3 subtitles):
  [1] 00:00:01,000 --> 00:00:03,000  =>  00:00:01,000 --> 00:00:03,000
  [2] 00:00:04,000 --> 00:00:06,000  =>  00:00:04,000 --> 00:00:06,000
  [3] 00:00:10,000 --> 00:00:12,000  =>  00:00:10,500 --> 00:00:12,500
```

### 3. Применить

```bash
sm delay --range 3-4 joined.srt +500
```

Уберите `--dry-run`, чтобы записать изменение; резервная копия сначала сохраняется в `backups/`.

> **Совет для отрицательных смещений:** ставьте флаги **перед** смещением
> (`sm delay --range 3-4 joined.srt -500`). Ведущий `-` делает смещение похожим на флаг,
> и флаги, размещённые после него, будут проигнорированы.

## JSON-вывод

```bash
sm --output json delay --range 3-4 joined.srt +500
```

```json
{"ok":true,"data":{"offset_ms":500,"subtitles_adjusted":2,"backup_path":"backups/joined.srt.2026-06-14_10-34-15.001252","range_start":3,"range_end":4}}
```

- `subtitles_adjusted` — количество перемещённых реплик.
- `range_start` / `range_end` — диапазон индексов, который был сдвинут (отсутствует при
  использовании `--from-timestamp`).

## Подводные камни и граничные случаи

- **`--range` и `--from-timestamp` взаимно исключают друг друга:**

  ```bash
  sm delay --range 3-4 --from-timestamp 00:00:09,000 joined.srt +500
  ```
  ```
  error: use either --range or --from-timestamp, not both
  ```

- **Без обоих флагов сдвигается весь файл** — это случай
  [постоянного смещения](detect-and-fix-constant-offset.ru.md).
- **`--range` включительный** и использует индексы субтитров (`START-END`), а не временны́е метки.
- **Измеряйте только на плохом участке.** Запускайте `sm detect-offset` относительно
  синхронизированного эталона, используя только рассинхронизированную часть, чтобы
  смещение не было разбавлено правильной первой половиной.
