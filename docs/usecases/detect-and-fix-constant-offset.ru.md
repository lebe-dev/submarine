# Обнаружение и исправление постоянного смещения синхронизации

> Субтитры стабильно опережают или запаздывают на фиксированную величину — измерьте сдвиг, затем исправьте весь файл одной командой.

## Сценарий

Субтитры соответствуют диалогу, но каждая строка появляется слишком рано или слишком
поздно на одну и ту же величину — классическое несовпадение между файлом субтитров и
версией видео. У вас есть эталон (другая дорожка с верной синхронизацией или собственный
тайминг видео), и вы хотите сдвинуть свой файл, чтобы он совпал.

## Используемые команды

- `sm detect-offset` ★ — измерить сдвиг относительно эталона
- `sm delay` — применить сдвиг ко всему файлу
- `sm detect-offset` снова — подтвердить, что результат равен ~0

## Файлы-примеры

`reference.srt` — с правильным таймингом:

```srt
1
00:00:10,000 --> 00:00:12,000
Good morning.

2
00:00:14,000 --> 00:00:16,000
How are you?

3
00:00:20,000 --> 00:00:22,000
See you tomorrow.
```

`subs.srt` — тот же диалог, запаздывающий на 2,5 секунды:

```srt
1
00:00:12,500 --> 00:00:14,500
Good morning.

2
00:00:16,500 --> 00:00:18,500
How are you?

3
00:00:22,500 --> 00:00:24,500
See you tomorrow.
```

## Пошаговая инструкция

### 1. Измерить смещение

```bash
sm detect-offset subs.srt reference.srt
```

```
Offset Detection
================

File A: subs.srt
File B: reference.srt

Anchor matches:     3
Median offset (ms): -2500
Stddev (ms):        0
```

`Median offset (ms): -2500` означает «файл A отстаёт от файла B на 2500 мс». `Stddev: 0`
подтверждает чистое постоянное смещение (без дрейфа), поэтому одного сдвига достаточно.
Чтобы вернуть `subs.srt` в синхронизацию, применяем отрицание этого отставания: **−2500 мс**.

### 2. Предварительный просмотр сдвига с `--dry-run`

```bash
sm delay --dry-run subs.srt -2500
```

```
Dry-run: time offset would be applied

Offset: -2500 ms
Subtitles affected: 3

Sample (first 3 subtitles):
  [1] 00:00:12,500 --> 00:00:14,500  =>  00:00:10,000 --> 00:00:12,000
  [2] 00:00:16,500 --> 00:00:18,500  =>  00:00:14,000 --> 00:00:16,000
  [3] 00:00:22,500 --> 00:00:24,500  =>  00:00:20,000 --> 00:00:22,000
```

В примере видно, что каждая строка попадает точно на тайминги эталона. Ничего не записывается.

> **Порядок флагов важен при отрицательном смещении.** Ведущий `-` делает смещение
> похожим на флаг, поэтому ставьте флаги опций (`--dry-run`, `--range`,
> `--from-timestamp`) **перед** смещением: `sm delay --dry-run subs.srt -2500`.
> Положительные смещения (`+2500`) не затронуты.

### 3. Применить

```bash
sm delay subs.srt -2500
```

```
✓ Time offset applied successfully

Backup: backups/subs.srt.2026-06-14_10-43-26.541735
Offset: -2500 ms
Subtitles adjusted: 3
```

`sm delay` изменяет файл на месте, предварительно записав копию с меткой времени в `backups/`.

### 4. Подтвердить

```bash
sm detect-offset subs.srt reference.srt
```

```
Median offset (ms): 0
```

Медиана `0` означает, что файлы теперь синхронизированы.

## JSON-вывод

```bash
sm --output json delay subs.srt -2500
```

```json
{"ok":true,"data":{"offset_ms":-2500,"subtitles_adjusted":1,"backup_path":"backups/subs.srt.2026-06-14_10-43-26.549470"}}
```

- `offset_ms` — применённый сдвиг.
- `subtitles_adjusted` — количество перемещённых реплик.
- `backup_path` — куда была записана копия до изменений (`N/A (dry-run)` при `--dry-run`).

И оболочка обнаружения, управляющая всем этим процессом:

```bash
sm --output json detect-offset subs.srt reference.srt
```

```json
{"ok":true,"data":{"anchor_matches":3,"median_offset_ms":-2500,"stddev_ms":0,"drift_detected":false,"same_video":false}}
```

`drift_detected:false` — сигнал того, что `delay` является правильным инструментом.

## Подводные камни и граничные случаи

- **Смещение должно содержать знак:** `+100` или `-500`. Голое `100` отклоняется.
- **Сдвиг назад может уйти в ноль.** `sm delay` отказывает в смещении, которое сдвинет
  любую строку раньше `00:00:00,000`. Проверьте с `--dry-run`, если видите ошибку
  отрицательного таймстампа.
- **Высокое `Stddev` / «drift detected» означает неправильный инструмент** — задержка
  нарастает со временем. Используйте [rescale](fix-framerate-drift-with-rescale.ru.md)
  вместо этого.
- **Только часть файла не в порядке?** См. [Ресинхронизация только части файла](resync-a-partial-range.ru.md).
