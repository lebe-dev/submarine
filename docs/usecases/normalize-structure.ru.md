# Нормализация структуры: сортировка, перенумерация, исправление перекрытий

> После ручного или скриптового редактирования приведите корректный SRT в порядок — отсортируйте по времени, перенумеруйте с 1, обрежьте перекрытия.

## Сценарий

Ручное редактирование или быстрый скрипт оставил файл в беспорядке: индексы больше не
возрастают, реплики не отсортированы по времени начала, пара соседних пересекается. Файл
ещё разбирается, но выглядит неряшливо. `sm normalize` переписывает его в каноническую форму.

## Используемые команды

- `sm normalize` ★ — сортировать, перенумеровать и опционально исправить перекрытия
- `sm doctor` — для другой задачи: восстановления структурных ошибок парсинга

## Файлы-примеры

`scram.srt` — в беспорядке, при этом первая реплика перекрывается со второй:

```srt
3
00:00:08,000 --> 00:00:10,000
Third in time.

1
00:00:01,000 --> 00:00:04,000
First, overlaps next.

2
00:00:03,000 --> 00:00:05,000
Second.
```

Реплика `1` заканчивается в `00:00:04,000`, но реплика `2` начинается в `00:00:03,000` —
перекрытие в 1 секунду.

## Пошаговая инструкция

### 1. Предварительный просмотр с `--dry-run`

```bash
sm normalize scram.srt --sort --renumber --fix-overlaps --dry-run
```

```
Dry-run: normalization would be applied

Sorted: yes (by start time)
Renumbered: yes (from 1)
Overlaps fixed: 1
Subtitles: 3
```

`Overlaps fixed: 1` — одна пара соседей, которая будет обрезана. Ничего не записывается.

### 2. Применить

```bash
sm normalize scram.srt --sort --renumber --fix-overlaps
```

```
✓ Subtitles normalized successfully

Backup: backups/scram.srt.2026-06-14_10-36-09.226844
Sorted: yes (by start time)
Renumbered: yes (from 1)
Overlaps fixed: 1
Subtitles: 3
```

Файл перезаписывается на месте (резервная копия сначала сохраняется в `backups/`). Реплики
теперь отсортированы, перенумерованы с 1, а перекрытие устранено обрезкой конца реплики 1
до начала реплики 2:

```srt
1
00:00:01,000 --> 00:00:03,000
First, overlaps next.

2
00:00:03,000 --> 00:00:05,000
Second.

3
00:00:08,000 --> 00:00:10,000
Third in time.
```

### Значения по умолчанию

`--sort` и `--renumber` **включены по умолчанию**, поэтому голый `sm normalize scram.srt`
уже переупорядочивает и перенумеровывает — но оставляет перекрытия нетронутыми:

```bash
sm normalize scram.srt --dry-run
```

```
Sorted: yes (by start time)
Renumbered: yes (from 1)
Overlaps fixed: no
```

Добавляйте `--fix-overlaps` только тогда, когда хотите обрезать тайминги соседей.

## JSON-вывод

```bash
sm --output json normalize scram.srt --sort --renumber --fix-overlaps --dry-run
```

```json
{"ok":true,"data":{"file":"scram.srt","total_count":3,"sorted":true,"renumbered":true,"overlaps_fixed":1,"backup_path":"N/A (dry-run)","dry_run":true}}
```

- `sorted` / `renumbered` — выполнялся ли каждый проход.
- `overlaps_fixed` — количество обрезанных перекрытий соседей.
- `total_count` — реплики после нормализации.

## `normalize` vs `doctor`

- `sm doctor` **диагностирует и исправляет структурные проблемы** — неверные временны́е коды,
  сломанные блоки реплик, ошибки парсинга. Используйте его, когда файл не загружается
  корректно.
- `sm normalize` предполагает, что файл уже **корректен**, и переупорядочивает,
  перенумеровывает и устраняет перекрытия. Сначала запустите `doctor` при ошибках парсинга,
  затем `normalize` для наведения порядка.

## Подводные камни и граничные случаи

- **`--fix-overlaps` изменяет тайминги**, а не только порядок — он обрезает конец реплики
  до начала следующей. Проверяйте с `--dry-run`.
- **Отключайте умолчание явно** через `--sort=false` / `--renumber=false`, если хотите
  перенумеровать без пересортировки или наоборот.
- **Перенумерация после слияния или ручной склейки** — типичный случай. Совмещайте с
  [dedupe](deduplicate-and-clean-after-merge.ru.md), если вкрались и почти-дубли.
