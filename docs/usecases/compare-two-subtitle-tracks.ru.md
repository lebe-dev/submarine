# Сравнение двух дорожек субтитров

> Узнайте реальное содержательное различие между двумя файлами субтитров — какие строки уникальны для каждого и какие отличаются лишь формулировкой.

## Сценарий

У вас есть две версии дорожки — два перевода, отредактированный и оригинальный варианты,
или релизная версия и ресинхронизированная — и вы хотите понять, чем они реально
отличаются: какие реплики совпадают, какие есть только в одной из версий, и где один и
тот же момент несёт другой текст.

## Используемые команды

- `sm diff` ★ — сравнение по пересечению временных окон или по тексту
- `sm verify` — для смежной, но другой задачи: «являются ли файлы структурно параллельными?»

## Файлы-примеры

`a.srt`:

```srt
1
00:00:01,000 --> 00:00:03,000
We need to leave now.

2
00:00:04,000 --> 00:00:06,000
Where are the keys?
```

`b.srt` — те же тайминги, одна строка перефразирована:

```srt
1
00:00:01,000 --> 00:00:03,000
We have to go now.

2
00:00:04,000 --> 00:00:06,000
Where are the keys?
```

## Пошаговая инструкция

### Сравнение по тексту

```bash
sm diff a.srt b.srt --by text
```

```
Diff between subtitle files
===========================

--- a.srt
+++ b.srt

Common:    1
Only in A: 1
Only in B: 1

- [1] 00:00:01,000 --> 00:00:03,000  We need to leave now.
+ [1] 00:00:01,000 --> 00:00:03,000  We have to go now.
```

`--by text` сопоставляет по нормализованному тексту. Одинаковая строка «Where are the keys?»
отнесена к `Common`; перефразированная первая строка появляется по одному разу с каждой
стороны (`Only in A` / `Only in B`) и отображается как пара `-`/`+` в стиле unified-diff.

### Сравнение по времени

```bash
sm diff a.srt b.srt --by time
```

```
Diff between subtitle files
===========================

--- a.srt
+++ b.srt

Common:    2
Only in A: 0
Only in B: 0
```

`--by time` (режим по умолчанию) сопоставляет по пересечению временных окон с допуском
`--tolerance` (по умолчанию `250` мс). Обе реплики занимают одинаковые окна, поэтому всё
является `Common` — даже несмотря на изменённую формулировку строки 1. Используйте этот
режим для поиска **структурных** различий (добавленные или удалённые строки, сдвиги);
используйте `--by text` для поиска различий в **формулировках**.

## JSON-вывод

```bash
sm --output json diff a.srt b.srt --by text
```

```json
{"ok":true,"data":{"a_file":"a.srt","b_file":"b.srt","by":"text","tolerance_ms":250,"only_in_a":[{"index":1,"start_time":"00:00:01,000","start_time_ms":1000,"end_time":"00:00:03,000","end_time_ms":3000,"duration_ms":2000,"text":"We need to leave now.","has_html":false}],"only_in_b":[{"index":1,"start_time":"00:00:01,000","start_time_ms":1000,"end_time":"00:00:03,000","end_time_ms":3000,"duration_ms":2000,"text":"We have to go now.","has_html":false}],"common_count":1}}
```

- `by` — использованный режим (`time` или `text`).
- `only_in_a` / `only_in_b` — полные записи реплик, присутствующих только на одной стороне.
- `common_count` — реплики, сопоставленные на обеих сторонах.

## `diff` vs `verify`

`sm diff` отвечает на вопрос «чем отличается содержимое?» — он сопоставляет реплики по
пересечению или по тексту и сообщает о несовпадающих. `sm verify` отвечает на более
строгий вопрос: «являются ли эти два файла параллельными по индексу и временной метке?»,
выводя процент совпадения и результат pass/fail. Для приведённых файлов-примеров `verify`
сообщает **SUCCESS** (обе реплики совпадают по индексу и тайминговому) — несмотря на
разные формулировки. Именно поэтому при интересе к содержимому нужен `diff`:

```bash
sm verify a.srt b.srt
```

```
Matched: 2/2 (100.0%)

Verification: SUCCESS
```

## Подводные камни и граничные случаи

- **Выбирайте режим под свой вопрос.** `--by time` игнорирует формулировки; `--by text`
  игнорирует тайминги. Перефразированная, но ресинхронизированная строка будет «общей»
  при `time` и «уникальной» при `text`.
- **`--tolerance` влияет только на `--by time`.** Увеличьте его для релизов, которые
  немного дрейфуют.
- **Текстовое сопоставление нормализовано** (пробелы/регистр), поэтому косметические
  различия не разделяют в остальном идентичные строки.
