# Удаление дублей и перекрытий после объединения

> После агрессивного слияния или склейки почти одинаковые строки накопились в почти одно время — схлопните их, затем приведите файл в порядок.

## Сценарий

Объединение дорожек оставило в файле почти-дубли: одна и та же строка появляется дважды
с разницей в несколько сотен миллисекунд, иногда один раз с форматированием `<i>`, а
другой раз без. `sm dedupe` схлопывает реплики с одинаковым (нормализованным) текстом,
перекрывающиеся по времени, оставляя одну объединённую реплику; `sm normalize` затем
пересортировывает и перенумеровывает.

## Используемые команды

- `sm dedupe` ★ — схлопнуть почти-дублирующиеся реплики
- `sm normalize` — финальная сортировка и перенумерация

## Файлы-примеры

`dup.srt` — каждая строка появляется дважды, с разницей ~50–100 мс, одна копия с HTML:

```srt
1
00:00:01,000 --> 00:00:03,000
<i>Hello there.</i>

2
00:00:01,100 --> 00:00:03,100
Hello there.

3
00:00:05,000 --> 00:00:07,000
A unique line.

4
00:00:05,050 --> 00:00:07,050
A unique line.
```

## Пошаговая инструкция

### 1. Предварительный просмотр с `--dry-run`

`--time-tolerance` — максимальное расстояние (в мс) между двумя репликами с одинаковым
текстом, при котором они всё равно считаются одной строкой; `--ignore-html` убирает теги
перед сравнением, так что `<i>Hello there.</i>` и `Hello there.` совпадают:

```bash
sm dedupe dup.srt --time-tolerance 200 --ignore-html --dry-run
```

```
Dry-run: duplicates would be removed

Time tolerance: 200 ms
Original subtitles: 4
Removed: 2
Merged groups: 2
Final subtitles: 2
```

Две пары схлопываются в две реплики: `Removed: 2`, `Merged groups: 2`, `Final subtitles: 2`.

### 2. Применить

```bash
sm dedupe dup.srt --time-tolerance 200 --ignore-html
```

```
✓ Duplicates removed successfully

Backup: backups/dup.srt.2026-06-14_10-36-09.200473
Original subtitles: 4
Removed: 2
Merged groups: 2
Final subtitles: 2
```

Каждая объединённая реплика сохраняет текст первого вхождения и охватывает объединение
двух окон (наиболее раннее начало, наиболее позднее окончание):

```srt
1
00:00:01,000 --> 00:00:03,100
<i>Hello there.</i>

2
00:00:05,000 --> 00:00:07,050
A unique line.
```

### 3. Привести в порядок

Перенумеровать и пересортировать очищенный файл:

```bash
sm normalize dup.srt
```

Подробности см. в [Нормализация структуры](normalize-structure.ru.md).

## JSON-вывод

```bash
sm --output json dedupe dup.srt --time-tolerance 200 --ignore-html --dry-run
```

```json
{"ok":true,"data":{"file":"dup.srt","original_count":4,"removed":2,"merged":2,"final_count":2,"time_tolerance_ms":200,"backup_path":"N/A (dry-run)","dry_run":true}}
```

- `original_count` / `final_count` — количество реплик до и после.
- `removed` — реплики, удалённые как дубли.
- `merged` — количество схлопнутых групп.

## Подводные камни и граничные случаи

- **`--time-tolerance 0` требует перекрывающихся окон** для слияния — схлопываются только
  реплики, реально пересекающиеся по времени и имеющие одинаковый текст. Увеличьте
  допуск, чтобы поймать копии, расположенные чуть поодаль.
- **Без `--ignore-html` различия в форматировании сохраняют реплики раздельными** —
  `<i>Hello</i>` и `Hello` воспринимаются как разный текст.
- **Текст первой реплики побеждает** в объединённой группе, поэтому курсивная копия может
  сохраниться вместо обычной (или наоборот) — зависит от порядка. После схлопывания
  запускайте [normalize](normalize-structure.ru.md) для перенумерации.
