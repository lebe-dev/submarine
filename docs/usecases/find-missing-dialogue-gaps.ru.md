# Поиск пропущенного диалога через анализ пауз

> Обнаружьте тихие промежутки в файле субтитров, где, возможно, был пропущен диалог.

## Сценарий

Перевод кажется неполным — в какой-то сцене, похоже, нет субтитров. Вместо того чтобы
перематывать видео, вы можете вывести список временных пауз между соседними репликами,
проверить подозрительные, а затем сравнить с файлом-донором, чтобы убедиться, что диалог
там действительно отсутствует.

## Используемые команды

- `sm gaps` ★ — список тишин длиннее заданного порога
- `sm info` — получить среднюю паузу в файле для выбора порога
- `sm diff` — проверить, есть ли диалог в паузе у файла-донора

## Пошаговая инструкция

В этом примере используется файл-пример, поставляемый с проектом,
`test-data/valid/complex.srt`.

### 1. Вывести список пауз

```bash
sm gaps test-data/valid/complex.srt --min-gap 1500
```

```
after index 2: 00:00:05,135 --> 00:00:07,790, duration 2.655s
```

Каждая строка сообщает о тишине: `after index 2` — реплика, после которой следует пауза,
затем окно (`конец реплики 2 → начало следующей`) и его длительность. Пауза в 2,655 секунды
после строки 2 — место для проверки.

### 2. Выбор `--min-gap`

`--min-gap` — нижний порог (в миллисекундах, по умолчанию `1000`), ниже которого паузы
игнорируются. Установите его чуть выше типичной паузы в файле, чтобы на поверхность
выходили только необычные тишины. `sm info` даст вам эту базовую линию:

```bash
sm info test-data/valid/complex.srt
```

Смотрите **Average gap between subtitles**. Если средняя пауза в файле ~9 с, пропущенная
сцена проявится как значительно бо́льший разрыв — начните с `--min-gap 15000`, чтобы
выделить только реальные дыры, затем снижайте, если подозреваете более мелкие пропуски.

### 3. Подтвердить по файлу-донору

Пауза сама по себе не доказывает, что диалог пропущен — там может просто не быть речи.
Сравните с более полной дорожкой для уверенности:

```bash
sm diff test-data/valid/complex.srt donor.srt --by time
```

Строки, попавшие в **Only in B** и находящиеся внутри паузы — это диалог, которого нет
в вашем файле. Это именно то, что нужно для [слияния с донором](merge-incomplete-translation-with-donor.ru.md).

## JSON-вывод

```bash
sm --output json gaps test-data/valid/complex.srt --min-gap 1500
```

```json
{"ok":true,"data":{"file":"test-data/valid/complex.srt","min_gap_ms":1500,"count":1,"gaps":[{"after_index":2,"start":"00:00:05,135","end":"00:00:07,790","duration_ms":2655}]}}
```

- `count` — количество пауз на уровне или выше `min_gap_ms`.
- `gaps[].after_index` — индекс реплики, после которой следует пауза.
- `gaps[].start` / `end` — тихое окно.
- `gaps[].duration_ms` — его длительность в миллисекундах.

## Подводные камни и граничные случаи

- **Пауза — не доказательство пропущенной строки.** Паузы, смены сцен и музыка — это
  норма. Перекрёстно проверяйте с `sm diff`, прежде чем делать вывод о пропущенном диалоге.
- **Порог в миллисекундах.** `--min-gap 1500` — это 1,5 с, а не 1500 с.
- **Перекрывающиеся реплики не создают паузы** (окно было бы отрицательным), поэтому
  они никогда не появляются в отчёте; устраните их с помощью [normalize](normalize-structure.ru.md).
