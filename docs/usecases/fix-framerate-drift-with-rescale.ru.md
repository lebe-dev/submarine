# Исправление дрейфа частоты кадров (23.976 ↔ 25)

> Синхронизация нормальна в начале, но всё больше уходит к концу — это несовпадение частоты кадров, а не постоянное смещение. Нужно растянуть временную шкалу, а не сдвигать её.

## Сценарий

Субтитры, созданные для релиза 25 fps (PAL), воспроизводятся с кодированием 23,976 fps
(NTSC/film), или наоборот. Ранние строки выглядят почти правильно, но ошибка линейно
нарастает до тех пор, пока последние строки не запаздывают на секунды. Один `delay` не
может это исправить — временна́я шкала должна быть *масштабирована*.

## Используемые команды

- `sm detect-offset` — подтвердить, что это дрейф, а не постоянное смещение
- `sm rescale` ★ — растянуть/сжать временную шкалу по коэффициенту, паре fps или двум якорным точкам

## Файлы-примеры

`movie.srt` — три реплики, распределённые на 20 минут:

```srt
1
00:00:10,000 --> 00:00:12,000
Opening line.

2
00:10:00,000 --> 00:10:02,000
Midpoint line.

3
00:20:00,000 --> 00:20:02,000
Closing line.
```

## Пошаговая инструкция

### 1. Подтвердить, что это дрейф, а не смещение

Сравните рассинхронизированный файл с синхронизированным эталоном:

```bash
sm detect-offset stretched.srt movie.srt
```

```
Median offset (ms): -25620
Stddev (ms):        20745

Note: drift detected (offset varies across the timeline); consider 'sm rescale'.
```

Показательны **большое `Stddev`** и явная пометка **«drift detected»**: измеренное
смещение мало вблизи начала и огромно ближе к концу. Эта изменчивость — признак
несовпадения частоты кадров; нужно использовать `rescale`, а не `delay`.

### 2. Масштабировать по паре fps

Если известны исходная и целевая частоты кадров, укажите их напрямую:

```bash
sm rescale movie.srt --from-fps 25 --to-fps 23.976 --out ntsc.srt --dry-run
```

```
Dry-run: rescale would be applied

Mode: fps
Factor: 1.0427093760427095
Offset: 0 ms
Subtitles affected: 3
Output: ntsc.srt

Sample (first 3 subtitles):
  [1] 00:00:10,000 --> 00:00:12,000  =>  00:00:10,427 --> 00:00:12,513
  [2] 00:10:00,000 --> 00:10:02,000  =>  00:10:25,626 --> 00:10:27,711
  [3] 00:20:00,000 --> 00:20:02,000  =>  00:20:51,251 --> 00:20:53,337
```

Коррекция растёт со временем — 0,4 с в начале, ~51 с на отметке 20 минут — точно отменяя
линейный дрейф. `sm` вычисляет коэффициент (25 / 23.976) за вас.

### 3. Или по явному коэффициенту

Если вы уже знаете множитель:

```bash
sm rescale movie.srt --factor 1.0427 --out scaled.srt --dry-run
```

```
Mode: factor
Factor: 1.0427
```

### 4. Или по двум якорным точкам

Когда fps неизвестна, но можно определить две реплики и временны́е коды, которые они
*должны* иметь, укажите две точки `--anchor IDX=HH:MM:SS,mmm`. `sm` вычислит линейное
преобразование, отображающее каждую реплику на цель (вычисляет и масштабный коэффициент,
и небольшое смещение):

```bash
sm rescale movie.srt --anchor "1=00:00:09,592" --anchor "3=00:19:10,096" --out anchored.srt --dry-run
```

```
Dry-run: rescale would be applied

Mode: anchor
Factor: 0.9584067226890757
Offset: 8 ms
Subtitles affected: 3
Output: anchored.srt

Sample (first 3 subtitles):
  [1] 00:00:10,000 --> 00:00:12,000  =>  00:00:09,592 --> 00:00:11,509
  [2] 00:10:00,000 --> 00:10:02,000  =>  00:09:35,052 --> 00:09:36,969
  [3] 00:20:00,000 --> 00:20:02,000  =>  00:19:10,096 --> 00:19:12,013
```

Реплики 1 и 3 попадают точно на запрошенные временны́е коды; всё между ними интерполируется.

### 5. Применить

```bash
sm rescale movie.srt --from-fps 25 --to-fps 23.976 --out ntsc.srt
```

```
✓ Rescale applied successfully

Mode: fps
Factor: 1.0427093760427095
Offset: 0 ms
Subtitles rescaled: 3
Output: ntsc.srt
Backup: N/A (new file)
```

## JSON-вывод

```bash
sm --output json rescale movie.srt --from-fps 25 --to-fps 23.976 --out ntsc.srt --dry-run
```

```json
{"ok":true,"data":{"file":"movie.srt","mode":"fps","factor":1.0427093760427095,"offset_ms":0,"total_count":3,"output":"ntsc.srt","backup_path":"N/A (dry-run)","dry_run":true}}
```

- `mode` — `factor`, `fps` или `anchor`.
- `factor` / `offset_ms` — вычисленное линейное преобразование `t' = factor·t + offset`.
- `output` — файл результата.

## Подводные камни и граничные случаи

- **Укажите ровно один режим.** `--factor`, пара `--from-fps`/`--to-fps` или два значения
  `--anchor` — их комбинирование или пропуск вызывает ошибку *«specify one of …»*.
- **`--out`, а не `--output`.** `--out` — файл результата; `--output text|json` — глобальный
  флаг формата.
- **В якорных временны́х кодах используется запятая** (`HH:MM:SS,mmm`). Берите каждый
  аргумент `--anchor` в кавычки, чтобы оболочка передала его без изменений.
- **Если `Stddev` близко к нулю** — это не дрейф; используйте [delay](detect-and-fix-constant-offset.ru.md).
