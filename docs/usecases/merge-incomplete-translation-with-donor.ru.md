# Дополнение неполного перевода из файла-донора

> Заполните дыры в частичном переводе строками из другого файла субтитров, не трогая строки, которым вы уже доверяете.

## Сценарий

У вас есть ручной перевод, в котором не хватает нескольких строк — сцена была пропущена
или переводчик остановился на полпути. Другой файл («донор») покрывает эти пропущенные
строки, но сдвинут на постоянную величину (другой релиз) и содержит одну лишнюю строку,
которой нет в вашем файле. Вы хотите сохранить собственные формулировки везде, где они
есть, и заимствовать строки донора только для пробелов.

Раньше это делалось с помощью специально написанных Python-скриптов. С `sm` — это одна
команда, которой предшествуют две быстрые диагностики.

## Используемые команды

- `sm detect-offset` — измерить постоянный временно́й сдвиг между двумя файлами
- `sm diff` — увидеть точно, что добавит донор
- `sm gaps` — найти дыры в базовом файле
- `sm merge` ★ — выполнить слияние с автоматической коррекцией смещения
- `sm info` / `sm verify` — подтвердить результат

## Файлы-примеры

Создайте эти два файла, чтобы следовать инструкции.

`base.srt` — ваш перевод, без строки около 00:00:10:

```srt
1
00:00:01,000 --> 00:00:03,000
Good morning.

2
00:00:04,000 --> 00:00:06,000
How are you?

3
00:00:20,000 --> 00:00:22,000
See you tomorrow.
```

`donor.srt` — тот же диалог, сдвинутый на +200 мс, с одной лишней строкой в дыре:

```srt
1
00:00:01,200 --> 00:00:03,200
Good morning.

2
00:00:04,200 --> 00:00:06,200
How are you?

3
00:00:10,200 --> 00:00:12,200
I missed you.

4
00:00:20,200 --> 00:00:22,200
See you tomorrow.
```

## Пошаговая инструкция

### 1. Измерить смещение между файлами

```bash
sm detect-offset base.srt donor.srt
```

```
Offset Detection
================

File A: base.srt
File B: donor.srt

Anchor matches:     3
Median offset (ms): 200
Stddev (ms):        0
```

`Median offset (ms): 200` означает, что донор постоянно отстаёт от базы на 200 мс.
`Stddev (ms)` равен `0`, что подтверждает равномерный сдвиг — одно смещение, а не
нарастающий дрейф. (При всего лишь трёх строках вы также можете увидеть заметку «files
share little dialogue»; эта эвристика предназначена для полнометражных файлов с сотнями
реплик и здесь её можно проигнорировать.)

### 2. Посмотреть, что добавит донор

```bash
sm diff base.srt donor.srt --by time
```

```
Diff between subtitle files
===========================

--- base.srt
+++ donor.srt

Common:    3
Only in A: 0
Only in B: 1

+ [3] 00:00:10,200 --> 00:00:12,200  I missed you.
```

Три строки перекрываются по времени (`Common: 3`) и ровно одна строка есть только в
доноре (`Only in B: 1`) — реплика `I missed you.`, заполняющая вашу дыру. `diff --by time`
сопоставляет по пересечению временного окна, поэтому сдвиг +200 мс не создаёт ложных
записей «only in B».

### 3. (Необязательно) Найти дыру в базе

```bash
sm gaps base.srt --min-gap 5000
```

```
after index 2: 00:00:06,000 --> 00:00:20,000, duration 14.000s
```

14-секундная тишина после строки 2 — это место для пропущенного диалога.

### 4. Предварительный просмотр слияния с `--dry-run`

```bash
sm merge base.srt donor.srt --out merged.srt --auto-offset --dry-run
```

```
Dry-run: merge would be applied

Strategy: fill-gaps
Applied offset: 200 ms

Base subtitles:  3
Donor subtitles: 4

Would add:     1
Would skip (overlapping): 3
Would replace: 0
Total after merge: 4

Output (not written): merged.srt
```

`--auto-offset` повторно использует обнаружение из шага 1 (`Applied offset: 200 ms`).
Стратегия `fill-gaps` по умолчанию добавляет только строку донора, попадающую в дыру
(`Would add: 1`), и пропускает три, перекрывающихся с вашими строками
(`Would skip (overlapping): 3`). Ничего ещё не записано.

### 5. Выполнить настоящее слияние

```bash
sm merge base.srt donor.srt --out merged.srt --auto-offset
```

```
✓ Merge completed successfully

Backup: N/A (new file)
Applied offset: 200 ms
Added: 1
Skipped (overlapping): 3
Replaced: 0
Total subtitles: 4
Output: merged.srt
```

`merged.srt` теперь содержит ваши три оригинальные строки плюс строку донора, сдвинутую
на обнаруженное смещение, чтобы она естественно вписалась в дыру:

```srt
3
00:00:10,400 --> 00:00:12,400
I missed you.
```

Когда `--out` указывает на существующий файл, `sm` записывает копию с меткой времени в
`backups/` перед перезаписью (здесь это новый файл, поэтому `Backup: N/A`).

#### Выбор стратегии

- `fill-gaps` (по умолчанию) — сохранять все строки базы; добавлять строки донора только
  там, где база молчит. Используйте для завершения перевода без его изменения.
- `keep-base` — никогда не заменять; идентично fill-gaps для добавлений, но отказывает
  при любом перекрытии. Наиболее безопасно, когда база является авторитетной.
- `prefer-donor` — когда строка донора перекрывается со строкой базы, заменять текст базы
  текстом донора. Используйте, когда донор является лучшим переводом.

`--overlap-tolerance` (по умолчанию `250` мс) контролирует, насколько небольшое
временно́е расхождение всё ещё считается «одной строкой», поглощая небольшие различия
в релизах, оставшиеся после применения смещения.

### 6. Проверить

```bash
sm info merged.srt
```

```
Subtitle File Information
========================

File: merged.srt

Basic Information:
  Total subtitles: 4
  Total duration:  00:00:21,000 (21.000s)
```

## JSON-вывод

```bash
sm --output json merge base.srt donor.srt --out merged.srt --auto-offset --dry-run
```

```json
{"ok":true,"data":{"base_count":3,"donor_count":4,"added":1,"skipped_overlapping":3,"replaced":0,"applied_offset_ms":200,"total_count":4,"output":"merged.srt","dry_run":true}}
```

- `added` — строки донора, вставленные в дыры.
- `skipped_overlapping` — строки донора, отброшенные из-за перекрытия со строкой базы.
- `replaced` — строки базы, перезаписанные (ненулевое только при `--prefer-donor`).
- `applied_offset_ms` — сдвиг, применённый к донору (из `--auto-offset` или `--offset`).
- `total_count` — количество субтитров после слияния.

## Подводные камни и граничные случаи

- **`--out`, а не `--output`.** `--out` — файл результата; `--output text|json` — глобальный
  флаг формата. Это разные флаги.
- **Строки донора, выходящие за временной диапазон базы, также добавляются**, а не только
  те, что в внутренних дырах. Проверяйте с `sm diff --by time` заранее.
- **Сопоставление по временно́й метке, а не по тексту**, поэтому короткие повторяющиеся
  строки (например, «Thanks») в доноре не будут спутаны со строками в других местах базы.
- **Передайте смещение вручную через `--offset`**, если `--auto-offset` даёт сбой (например,
  слишком мало общего диалога): `sm merge base.srt donor.srt --out merged.srt --offset=-212`.
  Используйте форму с `=` для отрицательных значений.
- **Дрейф, а не смещение?** Если `sm detect-offset` сообщает о большом `Stddev` или
  «drift detected», одно смещение не выровняет файлы — см.
  [Исправление дрейфа частоты кадров](fix-framerate-drift-with-rescale.ru.md).
